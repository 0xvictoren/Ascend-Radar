The terminal

The terminal has three columns (stacked on phones):

  1. Launches: every Ascend launch, newest first, with risk score, market cap, price change, volume, holders and Ascended progress. New launches flash as they appear.
  2. Token: the full breakdown for the selected launch.
  3. Alerts: the live feed. Click any alert to open its token.

Filtering and search

  • All / High risk / Low risk: filter by risk level.
  • Ascending: tokens at least 50% of the way to Ascended status that aren't high risk.
  • Search: type a symbol or part of a token address.

The header shows the data source (elysium-testnet or the simulator), the latest indexed block, and a green dot while the live stream is connected. The selected token is kept in the URL (/#0x…), so you can share a link straight to it.

Reading a score

Every token starts at 100, and each red flag subtracts points:

ScoreLevelWhat it means
70–100lowNo serious red flags found yet. Not a guarantee: new launches have little history.
40–69cautionSomething is off, such as concentrated holdings, a linked bundle or partial dev selling. Read the reasons.
0–39highStrong rug patterns: a large dev position, dev selling, a serial deployer, or an actual collapse.

Always read Why this score. Each line is a specific claim, such as "Linked wallets hold 18.2% of supply (largest group: 5 wallets, shared funder 0x3f…a1)", that you can check in the explorer. The full rule list is on What we built.

Scores change as the token trades. A token rated low at launch can turn high minutes later when the dev starts selling, which is what alerts are for.

Token page

  • Header: score ring, name, address, creator, and creator-role status (shows creator role now 0x… after a handoff, e.g. to a fee router). Buy on Ascend opens the token on Ascend's app. Explorer opens it on the Elysium explorer.
  • Stats: market cap, volume, holders, and Dev sold (the share of dev-linked tokens already sold, shown in red from 20% up).
  • Why this score: every signal with its points, worst first.
  • Price: 1-minute candles in the pool's quote token (usually USDC).
  • Linked wallets: groups of early buyers Radar believes are one operator. dev groups touch the creator; bundle groups don't. Each shows how much it bought early, how much it still holds, and why its wallets are linked.
  • Ascended progress: market cap, holders, volume and coordinated holdings against Ascend's criteria. The targets are placeholders until Ascend publishes the real thresholds.
  • Top holders and Trades: tagged dev, b1, b2… (bundle groups) or your watch label.

Amounts are in the pool's quote token. USDC pools show dollars, and others (e.g. WHYPE) show the token symbol.

Copy-alerts & Pro

In the Alerts column, enter a wallet address and an optional label, then press Watch. Every trade that wallet makes on Ascend then appears in your feed (and in Telegram or Discord, if connected).

If the server runs with Pro enabled, watching a wallet needs a Pro key:

  1. Press Watch. Radar shows the price, the subscription length and the treasury address.
  2. Send that amount of USDC on Elysium to the treasury. Paying a multiple buys more periods (2× the price = 2 periods).
  3. Paste the payment's transaction hash and press Activate.
  4. Radar checks the payment on-chain and saves your key in this browser. Keep a copy: it's shown once, and it also unlocks the API.

Each payment can activate only one key. Keys expire at the end of the paid period.

Telegram & Discord

For a server you run yourself, add these to .env and restart:

TELEGRAM_BOT_TOKEN=123456:ABC…   # from @BotFather
TELEGRAM_CHAT_ID=-100…           # your chat or channel id
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/…
PUBLIC_URL=https://radar.example.com   # so alerts link back to the token

Only new events are pushed; history replayed at startup stays out of your chats.

With a Pro key

curl -H "x-radar-key: rk_…" https://radar.example.com/api/v1/risk/0xTOKEN

Pay per call (x402)

Without a key, /api/v1/risk/:address answers 402 Payment Required with the price, asset, network and pay-to address in the x402 v1 format. Any x402 client can sign the USDC payment and retry with an X-PAYMENT header. Radar verifies and settles it, then returns the report with an X-PAYMENT-RESPONSE receipt.

Run your own

You need Node 22.18 or newer and nothing else.

npm install
npm run sync           # index Ascend's Elysium testnet history (first run ~15–25 min)
npm run dev:elysium    # terminal on http://localhost:8787, live
npm run backtest:real  # score the real history, write data/backtest-real.json

npm run dev            # simulated launches instead, no network needed

Useful settings (.env, see .env.example):

  • PRO_MODE=on, PRO_TREASURY, PRO_PRICE_USDC, PRO_DAYS: turn on and price subscriptions.
  • X402_PAY_TO, X402_NETWORK, X402_PRICE_ATOMIC: turn on pay-per-call.
  • QUOTE_USD=0xToken:price,…: give non-USD quote tokens a dollar price.
  • HUB_ADDRESSES: exchange or bridge wallets that must never link buyers.
  • ASCEND_LAUNCHPADS, ELYSIUM_RPC_URL, ELYSIUM_EXPLORER_API: point Radar at new deployments or at mainnet.

Run one Radar process per database: sync and the terminal both write to data/radar.db.

FAQ

A token is "low risk". Is it safe?

No. Low means Radar found none of the patterns it looks for. It can't see off-chain coordination, wallets funded independently from exchanges, or bundles routed through smart contracts.

Why are two wallets "linked"?

The cluster card says why: a shared funder (named), a direct token transfer, or near-identical buys in the same 2-second window. Faucets, bridges and very busy wallets never count as a shared funder.

Why does the Ascended progress look off?

Ascend has published the criteria (market cap, holders, volume, no coordinated accumulation) but not the thresholds. Radar's targets are placeholders.

Is this real money?

Not yet. Radar currently reads Ascend's Elysium testnet, where USDC is a mock with no value. It switches to mainnet when Ascend launches there.

Does "Buy on Ascend" earn Radar a fee?

Not yet. Ascend pays referrers 20% of referred swap fees, but it hasn't published how a referral attaches to a trade. The button is a plain link until it does.
